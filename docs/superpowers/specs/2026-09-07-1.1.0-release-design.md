# 1.1.0 Release Design

## Goal

Publish the current verified Apple Silicon-only release candidate as version 1.1.0.

## Scope

- Change current release metadata in `Resources/Info.plist` from 1.2.0 to 1.1.0.
- Align current user-facing version statements in `CHANGELOG.md`, `README.md`, and CI branch monitoring with 1.1.0.
- Preserve historical design and implementation documents that record the earlier 1.2.0 plan.
- Run strict tests and the full smoke test after the version change.
- Commit the version alignment, push `main`, verify GitHub Actions CI, then create and push the annotated `v1.1.0` tag.
- Verify the GitHub Release and its direct-distribution artifacts after the release workflow completes.

## Constraints

- Apple Silicon (`arm64`) is the only supported architecture.
- Minimum supported macOS version is 13.0.
- The release tag must exactly match `CFBundleShortVersionString`.
- Do not recreate, edit, or delete the existing `v1.0.0` release.

## Release Flow

The release workflow builds the direct-distribution ZIP and DMG and uploads both artifacts plus `SHA256SUMS` when a `v*` tag is pushed. Version alignment is complete only when local metadata, the pushed tag, and the created GitHub Release all identify 1.1.0.

## Verification

1. Run `swift test -Xswiftc -strict-concurrency=complete -Xswiftc -warnings-as-errors`.
2. Run `./run_smoke_test.sh` and confirm exact `arm64` App and CLI artifacts.
3. Verify the local commit is pushed to `origin/main` and the corresponding CI run succeeds.
4. Verify `v1.1.0` points to the published commit and GitHub Release contains ZIP, DMG, and SHA256 artifacts.
